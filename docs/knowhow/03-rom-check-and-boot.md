# 03 起動時の ROM チェックと、起動画面の版表示

## ROM チェックを通す

- 多くの基板は起動時に ROM の **偶数バイトの合計・奇数バイトの合計** を、ROM の中の期待値と比べ、違うと先に進まない（または NG を表示する）。改造したらブートが進まないときは、まずこれを疑う。
- 直し方は2通り:
  1. **期待値を書き換える**（期待値自身も合計に含まれるので、固定点になるまで繰り返す）
  2. **空き領域のバイトで合計を元に戻す**（`tools/romkit.py` の `lane_fix()`。各レーン 1バイトあたり最大 255 動かせる。足りなければ範囲を広げる）
- サブ CPU の ROM の合計をメイン側が持っている基板もある（gradius3 はメインの 0x744/0x748）。サブを改造したら、その値も直す。
- サウンド CPU（Z80）の ROM にもチェックがあることがある（gradius3 は 0x0000–0xEFFF の合計を 0xef00 で補正）。
- 合計の調整に使うバイトはコードと重ねない。調整用の範囲を最初に決めて、TECH.md に書いておく。

## 起動画面に版とビルド日時を書く

改造 ROM だとすぐ分かり、検証で「どのビルドか」を確かめられるようにする（gradius3 の v0.4.17〜）。

- 起動直後の「RAM ROM CHECK」などの文字列表を探し、そのポインタを、空き領域に置いた新しい文字列表へ向ける。
- 書く内容の例: 「`0 4 17  26 10 26 10:12`」＝版（数字を空白区切り）・空白2つ・年の下2桁 月 日 時:分。
  - **使う文字は、その画面で確実に出るものだけ**（数字・空白・コロンなど）。起動画面のフォントには「.」や記号が無いことが多い。Konami の起動画面は「文字＝タイル+0x30」で、`@` が空白、`>` の位置にコロンがあった。
  - 置ける大きさ（バイト数）を先に決め、それを超えたらビルドを止める。合計の調整に使う余りも残す。
- ビルドは必ず版を指定する（例 `VERSION=0.4.17`）。指定し忘れたら「0 0 0」のような、リリースに使えない値にする。
- **リリースのスクリプトは、ROM に書いた版とリリースの版が違えば止める**（ROM から読み戻して比べる）。
- 検証の手順書には「添付された ROM の起動画面の行を読み、対象の版・日時と一致しなければ検証を始めない」と書く。
- 書き換えたら、MAME で起動して表示と ROM チェックの通過（「OK」が並んでデモに進む）を確かめる。
