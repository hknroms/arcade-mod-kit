# 実例: グラディウスIII（hknroms/gradius3）

このひな形の元になったタイトル。詳しい番地は gradius3 の `docs/dev/TECH.md`。

## 基板・ROM

- メイン 68000（313版メイン: `945_313.f15` 偶数・`945_312.e15` 奇数）、サブ 68000（`945_m09.r17`・`945_m08.n17`）、サウンド Z80（`945_r05.d9`）。MAME のセット名 `gradius3`、ソース `src/mame/konami/gradius3.cpp`。
- 共有 RAM: メイン 0x100000 = サブ 0x200000。タイル K052109、スプライト K051960（サブ側）、文字 RAM はメイン 0x180000 = サブ 0x280000。

## 作ったもの

- スタート後のメニュー（モード・面・エリア・装備・ランクなど）、ポーズメニュー、キューブラッシュ・ボスラッシュ、CUBE LINE などの表示。
- 改造機能はメニューから始めたときだけ有効（MB_RUN）。通常プレイは純正どおり。
- 起動画面に版とビルド日時（「0 4 17  26 10 26 10:12」）。
- ROM チェック: メインの偶数・奇数の合計（期待値 0x73c/0x740）、サブ合計の写し（0x744/0x748）、サウンドの合計（0xef00 で補正）をすべて合わせている。

## 分かったこと（他のタイトルにも通じそうなもの）

- 死亡・再開時にゲームが使う RAM（0x103cb0–0x103cef）に自分の変数を置いたら、面が3面に飛ぶバグになった → 「死亡をまたいで残るか」を必ず確かめる（01）。
- ボス前の停止区間の進み方は時間で決まるので、開始位置をずらしても飛ばせない（01）。
- ビルドに、使っていない画面ダンプの読み込みが残っていて、前の会話の作業フォルダが無いとビルドできなかった → 直して、公開版と完全一致するビルドを確認（06）。
- MAME4droid は SHA-1 の照合で改造 ROM を一覧から起動できない（07）。
