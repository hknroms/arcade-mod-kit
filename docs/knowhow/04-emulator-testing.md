# 04 MAME での検証

## MAME を用意する

- タイトルのドライバだけを入れた小さな MAME を **1回だけ** ビルドし（`tools/build_mame.sh`、2コアで30〜60分）、枝 `mame-<名前>-bin` に置く（`tools/publish_mame.sh`）。以後のチャットはそれをダウンロードするだけ（数秒）。
- Claude のクラウドの会話からは GitHub の Releases を作れない（2026-10 時点）ので、枝に置く。
- ビルドで詰まった所（apt が使えず GitHub だけつながる環境、MAME 0.289）:
  - SDL2 / SDL2_ttf は GitHub の libsdl-org からソースでビルドして `/opt/sdl` へ。
  - `GL/gl.h` が無い → SDL の `SDL_opengl.h` を include するだけの `GL/gl.h` と、MAME 同梱の khronos の `EGL`・`KHR` を `/usr/local/include` に置く（`-I` は 3rdparty に効かないので標準の場所に）。
  - `XInput.h` が無い → `NO_X11=1 NO_USE_XINPUT=1`。ALSA が無い → `NO_USE_MIDI=1`。リンクで `-lEGL` が無い → `libEGL.so.1` への開発用リンクを作る。
  - これらのオプションを後から変えたら、`build/projects` を消して作り直させる（古い設定のまま進むことがある）。
  - 全部 `tools/build_mame.sh` に入れてある。

## 画面なしで回す

- `lua/run.sh <ROMのフォルダ> lua/run.lua <出力>`。`-video none -sound none -nothrottle` で実時間の10倍前後で進む。
- 入力は「何フレーム目にどのキー」で与える（`SEQ="1400:COIN,1500:START"`、長押しは `HOLDK`）。キーは MAME の入力名で探すので、どのドライバでも同じ書き方。
- `POKE` で RAM を書き換え（無敵・面の指定など）、`WATCH` で値の変化を記録、`SNAP` でスクリーンショット、`DUMPAT`/`DUMP` でメモリを保存。
- 同じ入力なら毎回同じ結果になる（決定的）。**再現手順は入力列と POKE で書く**と、誰でも同じ場面を出せる。
- 目的の場面まで長いなら、改造のメニュー（面選択）を使うか、POKE で飛ばす。

## 分かること・分からないこと

- 分かる: CPU・RAM の動き、静止画（スナップ）、ROM チェックの通過、表示の崩れ（明らかなもの）。
- 分からない（人の目で確認）: 色の微妙さ、音、体感速度、ちらつき、実機との違い。報告では断定しない。
- **純正と比べる**: 改造版で起きたことが純正でも起きるか、同じ入力で比べる。純正でも起きるなら MAME 側の問題の可能性がある。

## 検証の報告

- 版とビルド日時（起動画面）、確認項目ごとの ok/ng/hold、根拠（何フレーム目に何が起きたか）、ng の再現手順（そのまま再実行できる形）。
- ROM の中身やダンプは公開の場所に貼らない。スクリーンショットは貼ってよい（人に貼ってもらう）。
