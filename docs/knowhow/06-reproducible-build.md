# 06 誰でも同じものをビルドできるようにする

チャットや人が替わっても続けられるように、**リポジトリと純正 ROM だけで、公開中の版とまったく同じものがビルドできる**状態を保つ。

## ROM 由来のデータは置かず、作り方を置く

- ROM の中身・RAM ダンプ・画面のダンプ・ステートセーブは、公開のリポジトリに入れない。
- ビルドにそれらが要るときは、**作るスクリプト（MAME を回してその場面を保存する入力列と保存範囲）をリポジトリに置き、ビルドのたびに作る**。
- 作り方が正しいかは、作ったものの一部（例: パレット）がリポジトリにある正解と一致するかで確かめる。
- gradius3 では、メニュー背景の材料のうち 2つ（VRAM・文字 RAM のダンプ）がリポジトリに無く、前の会話の作業フォルダにしか無かった。実際には使っていないデータだったので、無くてもビルドできるように直した。**「使っていないファイルを読む」コードも、ビルドを止める原因になる**。

## 作業フォルダのパスを書き込まない

- 前の会話の一時フォルダ（`/tmp/claude-0/...`）をソースに直接書いていると、次の会話では動かない。ROM の置き場所は環境変数（`ROMBASE` など）、リポジトリ内のファイルは `__file__` からの相対で探す。
- 引き継ぎのたびに「作業フォルダにしか無いもの」が無いか確かめる。見つけたら、リポジトリに入れる（公開してよいもの）か、作り方に置き換える。

## 公開中の版を再現できるか確かめる

- 配布しているパッチ（BPS）の「当てた後の CRC」を `docs/versions.json` に記録しておく。
- 純正 ROM からビルドして、その CRC と全ファイル一致するかを確かめる（ビルド日時は当時の値を指定して再現する）。一致すれば、リポジトリだけで作れることの証明になる。
- gradius3 は 2026-10-26 に v0.4.16 の5ファイルすべてが一致した。

## 記録の置き場所

- いまの状態は `docs/dev/STATUS.md`、技術メモは `docs/dev/TECH.md`、1件ずつの作業は Issue。チャットの引き継ぎファイルは作らない（CLAUDE.md の 0.5）。
