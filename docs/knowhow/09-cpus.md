# 09 CPU ごとの違い（68000 以外の基板）

このひな形は CPU を問わずに使える。01〜05 は 68000（グラディウスIII）の例で書いてあるので、ほかの CPU ではこのページの違いを読み替える。

## そのまま使えるもの（CPU に関係ない）

- 共同作業の仕組み（ボット・まとめページ・手順書）、記録の置き場所（STATUS.md・TECH.md・Issue）
- MAME のビルドと配置（`tools/build_mame.sh` はドライバのソースを指定するだけ）、MAME を回すスクリプト（`lua/run.lua`。`CPU=":audiocpu"` のように対象の CPU を選べる）
- BPS パッチ・リリース・配布ページの考え方
- ROM の組み立て（`tools/romkit.py`）: 1本・2本・4本の並べ方、16bit 単位の並べ方、空き領域の確認、重なりの検出、レーンごとの合計の補正

## CPU ごとに変わるもの

| CPU | ROM の並べ方 | 番地の並び | 起動・割り込みの入口 | 注意 |
|---|---|---|---|---|
| 68000 系 | 2本（偶数・奇数）| ビッグエンディアン | 先頭のベクタ表（SSP・PC・割り込み） | asm68 / d68 がある |
| Z80 | 1本（大きいものはバンク切り替え） | リトルエンディアン | 0x0000、RST は 0x00〜0x38、NMI 0x66、IM2 は表 | サウンド CPU に多い。バンクの切り替えを追う |
| 6809（コナミ独自の「KONAMI」CPU を含む） | 1本 | ビッグエンディアン | 末尾 0xFFF0〜0xFFFF のベクタ | コナミの改造 6809 は命令が暗号化されている（下の「暗号化」） |
| 6502 / HuC6280 | 1本 | リトルエンディアン | 末尾 0xFFFA〜0xFFFF のベクタ | ゼロページの使い方を追う |
| V30 / 8086 系 | 2本（偶数・奇数） | リトルエンディアン | 0xFFFF0 から、割り込み表は 0x0000 | セグメントに注意 |
| SH-2 / V60 / 68020 などの 32bit | 4本、または 16bit 単位で2本（`width: 2`） | 機種による | 機種ごとのベクタ | 並べ方は MAME の `ROM_LOAD32_BYTE`／`ROM_LOAD32_WORD` で確かめる |

- **並べ方の確かめ方**: MAME のドライバのソースの `ROM_START` の中を見る。`ROM_LOAD`（1本）、`ROM_LOAD16_BYTE`（2本・1バイトずつ）、`ROM_LOAD16_WORD_SWAP`（1本・16bit・バイト順入れ替え）、`ROM_LOAD32_BYTE`（4本）、`ROM_LOAD32_WORD`（2本・16bit 単位）など。読み込み位置（オフセット）と合わせて `title.json` の `groups` を書く。`WORD_SWAP` の ROM は、読み込んだ後に2バイトずつ入れ替えてから扱う。

## 起動時の ROM チェック

- 8bit 機は「全体のバイトの合計（下位 8bit や 16bit）」が多い → `lane_fix(..., lanes=1)`。
- 16bit 単位・32bit 単位の合計や、CRC で比べる基板もある。その場合は合計の式をチェックのルーチンから読み取り、合わせ方をタイトルの `src/` に書く（`lane_fix` は1バイトずつの合計用）。
- チェックの結果を画面に出す基板（「ROM OK」など）は、MAME のスナップで通過を確かめる。

## 暗号化された基板

- コナミの「KONAMI」CPU（6809 改造）、セガの FD1094 / FD1089（68000）、カプコンの CPS2・Kabuki（Z80）など、**ROM の命令が暗号化されている基板がある**。MAME のドライバに復号の処理があれば暗号化されている。
- 改造するときは「復号 → 改造 → 同じ方式で暗号化し直す」が要る。暗号化し直せない方式もあるので、**始める前に MAME のソースで方式を確かめ、TECH.md に書く**。
- データ（グラフィック・テーブル）は暗号化されていないことが多いので、データだけの改造なら影響しないこともある。

## アセンブラと逆アセンブラ

- **逆アセンブル**: どの CPU でも、MAME の `unidasm` で逆アセンブルできる（`TOOLS=1 tools/build_mame.sh` で一緒に作ると、ビルド済みの tar.gz に入る）。例 `unidasm prog.bin -arch z80 -basepc 0`。MAME のデバッガでも見られる。
- **アセンブル**: 68000 は `tools/asm68.py`。ほかの CPU は、
  1. 小さな改造なら機械語を手で書いて `Rom.put()` で置く（命令表を見ながら）。
  2. よく使うなら、asm68.py と同じ形（`assemble(src, org, labels) -> (bytes, labels)`）のアセンブラを `tools/asm_<CPU名>.py` として作る。`romkit.Rom.asm()` は `title.json` の `arch` を見て `asm_<arch>` を自動で使う。
  3. 作ったアセンブラは arcade-mod-kit の `tools/` にも足して、次のタイトルで使えるようにする。
- アセンブラは、`unidasm` の逆アセンブル結果と突き合わせて確かめる（アセンブルしたものを逆アセンブルして元の文と一致するか）。

## 起動画面の版表示

- 68000 の例（03）と同じ考え方で、起動直後に文字を出しているルーチンと文字列表を探す。8bit 機はポインタが 16bit・リトルエンディアン（Z80・6502）のことが多い。
- 起動直後に文字を出さない基板では、タイトル画面の空いている所や、サービスモードの画面に出す。
