# 02 パッチの入れ方

## 置き場所

- **空き領域**: ROM の中で 0xFF（または 0x00）が続く所。`tools/romkit.py` の `Rom.put()` は、元が一色の所にしか書かせず、重なりも止める。どこに何を書いたかは `report()` で一覧できる。
- 空き領域の一覧と使い道は、タイトルの TECH.md の先頭に書いておく（例: gradius3 は A=0xd4aa 425B / B=0xd8f6 532B / C=0x3fd9a〜）。
- 足りなくなったら、使われていないデータ（デバッグ用の文字列など）を探す。消してよいかは実測で確かめる。

## アセンブラ（tools/asm68.py）

- 命令の大きさを固定（分岐は .w、絶対番地は .l）して1回目で番地を決め、2回目で値を入れる。
- 使える命令: move/movea/moveq/lea/add/sub/and/or/eor/cmp/adda/suba/各 immediate/addq/subq/clr/tst/neg/not/btst/bset/bclr/bra/bsr/Bcc/dbf/jsr/jmp/rts/nop/ext/swap/シフト系/mulu。movem は `dc.w` で直接書く（例 `dc.w $48e7,$f8fc` / `$4cdf,$3f1f`）。
- 制約: オペランドに式は書けない（`TILEA+$298` は不可、数値で書く）。`bcc.s` が届かないときは `.w` に。奇数番地のワード読みは不可（68000 の制約）。`(sp)` は `(a7)` と書く。
- 文字列はゲームのタイルコードに変換して置く（フォントの並びはタイトルごとに TECH.md へ）。

## フック

- 6バイトの命令（例 `addq.b #1,abs.l`）を `jsr 新しいルーチン` に置き換え、置き換えた命令の働きは新しいルーチンの中で再現する。8バイトなら `jsr`(6)+`nop`(2)。
- 置き換える前のバイトは `put(..., expect=元のバイト)` で必ず確かめる（版違いの ROM に当ててしまう事故を防ぐ）。
- 戻り先を変えたいときは、スタック上の戻り番地を書き換えて `rts`。

## ディスパッチテーブルの拡張

- テーブルの先頭を指す `lea` の long を新しいテーブルへ書き換え、元のエントリを写して末尾に新しいモードを足す。

## レジスタ

- 割り込みの中で、ディスパッチの後に全レジスタが戻される作りなら自由に使える。
- ゲームの途中のサブルーチンにフックする場合は、使うレジスタを必ず退避する。

## 失敗しやすい点

- 自作の変数をゲーム開始時のクリア範囲に置くと消える。
- フラグやカウンタが `subq` でアンダーフローしないよう、フック側で下限を補正する。
- 同時に出せる弾の数のような上限は、スプライト RAM のオブジェクト枠の数（物理的な上限）を超えられない。
- 速度のような低いレベルの定数の書き換えは、通常プレイに副作用が出やすい。**通常プレイは純正どおり**にし、改造機能は改造メニューから始めたときだけ有効にする（gradius3 の MB_RUN の考え方）。
- MAME では属性ビットの一部がタイルバンクに使われて文字が化けることがある（自作エミュレータでは化けない）。ゲームがもともと使っている属性値だけを使う。カーソルは色ではなく専用の文字で示す（色は環境で変わる）。
